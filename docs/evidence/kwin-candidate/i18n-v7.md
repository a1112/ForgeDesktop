## Automated verification

- 47 ForgeDesktop tools tests passed on Windows and Linux. Missing/malformed
  catalogues, changed placeholders, unreviewed locale paths and translated Exec
  keys are rejected. Staged asset modes are explicit, independent of host umask.
- GNU gettext `msgfmt --check --check-format` passed, and regeneration matched
  the shipped binary byte-for-byte. Build host gettext: Ubuntu 0.23.2-1.
- ForgeOS Linux gates passed: Cargo fmt/check/test/clippy (locked/offline), schema,
  ownership-boundary, kernel, image, source-lock and license checks; 214 Python
  tests; required bash syntax checks. Existing CRLF shell scripts in the exported
  source were normalized to LF for Linux execution. Windows Python 3.9 lacks
  tomllib, so its full Python suite is not used as the acceptance result.
- Image build verified signed packages and generated locales; independent offline
  inspection checked all 18 installed bundle payloads against receipt hashes.

## Known upstream/runtime limits

- The pinned Region & Language KCM reports that automatic locale generation is
  unsupported on this distribution. Both accepted locales were already generated
  and both switch tests passed. The message disappears when settings is reopened.
  Other languages may require additional locale generation and application packs.
- Before v7 launch, v6 was already locked. ACPI shutdown was ignored; console
  restart reached shutdown but KWin/kscreenlocker remained in a kernel wait, with
  a hung-task report exceeding 247 seconds. No language changes were installed in
  v6. QEMU file migration completed before exit, preserving 3,355,084,455 bytes of
  VM state plus an offline `before-i18n-v7` disk snapshot and NVRAM copy. Files are
  under `/srv/forge-desktop-build/kwin-v6-test-vm/`. This is a saved stalled guest,
  not a successful normal shutdown. The two v7 language-change restarts succeeded;
  the earlier lock/exit fault remains a separate acceptance issue.

For forensic recovery, retain the v6 disk snapshot, matching NVRAM copy and
`before-i18n-v7.vmstate` together, plus the original run's `started.json` QEMU
configuration. Use the same QEMU version with `-incoming defer` and the file
migration transport; do not cold-start over the saved state and call it restored.
The image and all earlier overlays are retained.
